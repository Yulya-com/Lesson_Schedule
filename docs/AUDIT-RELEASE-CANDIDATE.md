## 2. Падение сервера от одного запроса с битым URL

**Уровень риска: высокий**

**Файл и место:** `serve.js`, строка 26 — `decodeURIComponent(...)` внутри `safePath()`;
вызов на строке 36 находится вне `try/catch` (тот `try` начинается на строке 52).

**Как воспроизвести:**
```powershell
Invoke-WebRequest "http://localhost:5173/app/%E0%A4%A" -UseBasicParsing
```
Соединение обрывается, процесс завершается с `URIError: URI malformed`.

**Почему опасно:**
Отказ в обслуживании одной строкой запроса. Ошибка в асинхронном обработчике
становится unhandled rejection, в Node.js 15+ это завершение процесса.
Практическое следствие — «проект не запускается» до ручного перезапуска.

**Минимальное исправление:** обернуть разбор URL в `try/catch`, возвращать 400.

**Как доказать:** запрос с `%E0%A4%A` даёт 400 без трассировки, сервер продолжает отвечать.

### Что фактически сделано

В `serve.js` разбор адреса обёрнут в `try/catch` внутри `safePath()`, добавлен
результат `{ badRequest: true }`, а в обработчике запроса — ветка ответа
`400 Некорректный адрес`. Дополнительно весь вызов `safePath` обёрнут в `try/catch`
на случай любой другой ошибки разбора.

### Результат проверки

```
GET /app/%E0%A4%A  -> HTTP 400
сервер после запроса -> работает (порт 5173 слушает)
в консоли сервера -> трассировки нет, процесс не завершился
```

## 3. Сервер отдаёт весь корень проекта

**Уровень риска: высокий**

**Файл и место:** `serve.js`, строки 30–32 — проверка `target.startsWith(ROOT + sep)`
разрешает любой файл внутри корня, а не только внутри `app/`.

**Как воспроизвести** (фактически выполнено): `/AGENTS.md`, `/README.md`,
`/serve.js`, `/docs/PROJECT-BRIEF.md`, `/.gitignore`, `/.git/config`, `/.git/HEAD` — все отдают 200.

**Почему опасно:**
Открыт `.git/`, раскрыт email владельца и адрес репозитория. Главное: как только
в корне появится резервная копия `tutorflow-*.json`, она станет скачиваемой по
адресу `http://localhost:5173/tutorflow-2026-10-27.json` со всеми ФИО,
телефонами и ставками учеников.

**Минимальное исправление:** разрешить только каталог `app/`.

**Как доказать:** `/app/app.js` → 200, `/AGENTS.md` и `/.git/config` → 403 или 404.

### Что фактически сделано

В `serve.js` добавлена константа `PUBLIC_DIR = <корень>/app`. Логика `safePath`:

- всё, что не начинается с `/app/`, отсекается флагом `forbidden` **до** обращения
  к файловой системе;
- путь нормализуется относительно `PUBLIC_DIR`;
- дополнительно блокируется символ `\0` и выход за пределы `PUBLIC_DIR`;
- `/` и `/app` отдают редирект на `/app/`.

Также убрана печать абсолютного пути в консоль запуска: теперь выводятся
только адрес, пояснение и адрес прослушивания.

### Результат проверки

Доступно:
```
/app/              -> 200
/app/index.html    -> 200
/app/app.js        -> 200
/app/styles.css    -> 200
/                  -> 302 (редирект на /app/)
```

Закрыто:
```
/docs/PROJECT-BRIEF.md        -> 403
/docs/AUDIT-RELEASE-CANDIDATE.md -> 403
/AGENTS.md                    -> 403
/README.md                    -> 403
/serve.js                     -> 403
/.git/config                  -> 403
/.git/HEAD                    -> 403
/.gitignore                   -> 403
/.env                         -> 403
```

Попытки обхода закрыты:
```
/app/../docs/PROJECT-BRIEF.md   -> 403
/app/..%2fdocs/PROJECT-BRIEF.md -> 403
/app/%2e%2e/docs/PROJECT-BRIEF.md -> 403
/app/../../.env                 -> 403
/app/../serve.js                -> 403
/app/%00.js                     -> 403
/APP/app.js                     -> 403
```

Приложение при этом работает: страница открывается, 5 разделов на месте,
IndexedDB версии 2 читается, консоль браузера без ошибок.

**Важно для пользователя:** документация по-прежнему доступна — но только
как файлы в папке `docs/`, а не через браузер.

## 5. Импорт копии стирает данные без страховки

**Уровень риска: средний**

сначала `clear()` всех хранилищ, затем запись с `try/catch` внутри цикла.

ошибки записей считать проваливанием импорта целиком.

**Как доказать:** импорт частично битого файла → ошибка, прежние 10 учеников на месте,
в загрузках появился файл копии.

## 12. `validateBackup` пропускает копию без `schemaVersion`

**Уровень риска: низкий**

**Файл и место:** `app/db.js` — `if (Number(data.schemaVersion) > DB_VERSION) throw ...`

**Как воспроизвести:** `db.validateBackup({ app: "TutorFlow", students: [], lessons: [] })`
— исключения нет.

**Почему опасно:** `Number(undefined)` даёт `NaN`, а `NaN > 2` — `false`.
Копия неизвестного формата проходит проверку.

**Минимальное исправление:** требовать целое `schemaVersion >= 1`.

**Как доказать:** без версии → ошибка; `1` → принято; `99` → ошибка. Оформить тестом.

### №5. Импорт больше не стирает данные

`app/db.js` — `importData()` переписан:

- сначала проверяются **все** записи файла, ошибки собираются в список `problems`;
- заметки принимаются только к занятиям, которые есть в этом же файле;
- если есть хоть одна ошибка — `importData` бросает исключение и **не открывает
  транзакцию**: база остаётся нетронутой;
- настройки пишутся через `sanitizeSettingsRecords`.

`app/app.js` — `importBackup()`:

- перед заменой автоматически скачивается копия текущих данных
  (`tutorflow-before-import-<дата>.json`), её имя показывается в уведомлении;
- если копию сохранить не удалось, приложение спрашивает, продолжать ли без страховки;
- ошибки записей показываются списком в окне «Импорт отменён», а не одной строкой.

Проверено: файл с битым учеником → окно «Импорт отменён», «Ученик №2: Имя —
не короче 2 символов», учеников в базе по-прежнему 0; корректный файл →
«Импортировано: учеников 1… Прежние данные сохранены в файл
tutorflow-before-import-2026-10-28.json».

**Найденная при проверке регрессия и её исправление.** После ужесточения
`validateBackup` (№12) импорт через интерфейс перестал работать совсем:
`validateBackup` возвращал объект без `schemaVersion`, а `importData` проверяет
переданные данные ещё раз и не находил версию. Теперь `validateBackup`
возвращает `app` и `schemaVersion` вместе с данными; на это добавлен тест

`app/ui.js` разбирает строку стиля и применяет свойства через CSSOM
(`node.style.setProperty`), что CSP не блокирует. Заодно убраны два инлайновых
стиля из `app/index.html` (сообщение `<noscript>`) и из страницы 404 в `serve.js` —
им добавлены классы `.noscript` и обычный текст.
