# TutorFlow — план реализации

Версия 2. Учтены согласованные решения: название TutorFlow, демо-данные,
серия создаётся сразу целиком, отмена в рамках сеанса, настраиваемый график
работы, сводка недели, запрет занятия без ученика.

**Статус: реализовано полностью, этапы 0–10 закрыты.**
Отчёт по проверкам — в разделе 12.

## 1. Продукт в одном абзаце

TutorFlow — локальное веб-приложение для одного репетитора. Открывается и сразу
показывает неделю целиком: 7 дней по горизонтали, время по вертикали, все занятия
цветными блоками. Занятие можно перетащить на другое время или день, открыть
и дописать заметку, отметить проведённым и оплаченным. Ученики живут в отдельном
справочнике с предметом, контактом и ставкой; из карточки ученика видно его
историю и суммы. Повторяющиеся занятия создаются серией и дальше живут как
обычные занятия, которые можно переносить по одному.

## 2. Экраны

| Экран | Что на нём | Ключевые действия |
|---|---|---|
| Расписание · Неделя | Сетка 7 × время, шапка с датами, линия «сейчас», блоки занятий | Создать в слоте, открыть, перетащить, растянуть длительность |
| Расписание · Месяц | Сетка 6 × 7, чипы занятий, «+N ещё» | Перейти к неделе, создать занятие |
| Расписание · Список | Занятия месяца по датам, фильтры, поиск | Открыть, отметить статус и оплату |
| Ученики | Поиск, карточки, суммы, регулярное расписание | Создать, изменить, архивировать, открыть историю |
| Заметки | Все заметки, поиск по тексту и ученику | Открыть занятие, править заметку |
| Сводка | Неделя и месяц: часы, суммы, долг по ученикам | Перейти к занятию, отметить оплату |
| Настройки | График работы, значения по умолчанию, данные | Демо, экспорт и импорт JSON, очистка |

## 3. Модель данных и связи

```
student 1 ──< lesson >── 1 series
                 │
                 └── 1 note
```

- `lesson.studentId` → `students.id`. Удаление ученика заменено архивом,
  история занятий сохраняется.
- `lesson.seriesId` → `series.id`, `null` для разовых занятий.
- `lesson.occurrenceDate` — дата, на которую занятие поставило правило.
- `lesson.occurrenceKey` = `seriesId|occurrenceDate`, уникальный индекс.
  У разовых занятий поля нет, поэтому уникальность на них не действует.
- `lesson.detached = true` — занятие вынули из серии, правило его не трогает.
- `series.exceptions` — даты, которые серия больше не создаёт.
- `note.lessonId` → `lessons.id`, одна заметка на занятие.

## 4. Как работают повторы

1. Пользователь создаёт занятие и включает «Повторять».
2. Выбирает дни недели, интервал в неделях, время, длительность и дату окончания.
3. `recurrence.js` строит список дат чистой функцией:
   старт от `startDate`, фильтр по дням недели, выравнивание по неделе старта,
   шаг `intervalWeeks × 7` дней, обрезка по `endDate`.
4. Серия создаётся **сразу целиком** одной транзакцией: запись `series`
   и все занятия до даты окончания.
5. Защитный лимит — 400 занятий. Если правило даёт больше, приложение
   предупреждает и предлагает создать первые 400.
6. При правке занятия из серии спрашиваем: «Только это занятие» или «Всё будущее».
   - «Только это» → `detached = true`, дата попадает в исключения серии.
   - «Всё будущее» → правило обновляется, будущие `planned` и неотвязанные
     занятия пересоздаются; прошедшие, `done`, `cancelled` и `detached` остаются.
7. Перенос занятия серии = `detached` + исключение на исходную дату.
8. Удаление одного занятия серии = исключение, чтобы оно не воскресло.
9. Удаление серии = удаление будущих занятий, прошедшие остаются в истории.

Проверка правил — `app/recurrence.test.js` на `node --test`, без зависимостей.

## 5. Перенос занятий

- Перетаскивание за блок, шаг привязки — шаг сетки (по умолчанию 30 минут,
  минимум 15).
- Растягивание нижней границы блока меняет длительность (15–240 минут).
- Жёсткий конфликт с занятием того же ученика блокирует перенос.
- Конфликт с другим учеником — предупреждение с подтверждением.
- Изменение сразу пишется в IndexedDB, внизу появляется уведомление
  «Перенесено на 25.10, 18:30 — Отменить» на 8 секунд.
- Без мыши: `Alt` + стрелки для занятия в фокусе, плюс поля даты и времени в форме.
- На экранах уже 768 пикселей drag отключается, перенос доступен через форму.

## 6. Сводка недели

Панель над сеткой, обновляется при любом изменении:

| Показатель | Что считается |
|---|---|
| Занятий | Все занятия периода, кроме отменённых |
| Часов | Сумма длительностей ÷ 60, один знак после запятой |
| Проведено | Количество занятий со статусом «проведено» |
| К оплате | Сумма стоимости занятий «запланировано» и «проведено» с `paid = false` |

Правила расчёта:

- `cancelled` не входит ни в один показатель.
- `noShow` не входит в «Часов» и в «К оплате».
- Единственный источник сумм — `lesson.price` и `lesson.paid`; сводка только читает.
- Клик по «К оплате» открывает список неоплаченных занятий периода.

## 7. График работы

Раздел «Настройки» → «График работы»:

- начало и конец рабочего дня (по умолчанию 08:00–22:00);
- шаг сетки 15 / 30 / 60 минут;
- рабочие дни недели; нерабочие приглушены и помечены «выходной»;
- показ выходных;
- длительность занятия и ставка по умолчанию.

Хранение: `settings.workHours = { start, end, step, workdays, showWeekends }`,
`settings.defaults = { duration, rate }`. Применяется сразу, без перезагрузки.
Занятие вне графика всё равно видно: сетка расширяется до его времени.

## 9. Правила валидации

- Ученик: имя обязательно, 2–60 символов; предмет обязателен; контакт
  необязателен, но если заполнен — телефон, @ник или email; ставка ≥ 0.
- Занятие: ученик выбран, дата и время заполнены, длительность 15–240, шаг 15.
- Серия: выбран хотя бы один день недели, дата окончания позже начала,
  не больше 400 занятий.
- Ошибки — рядом с полем, текстом «что не так и как исправить».
- Кнопка сохранения блокируется, пока не заполнены ученик, дата и время.
- Форма не закрывается при ошибке, введённые значения не теряются.

## 13. Имя и фамилия

Добавлено после первой версии. Ученик хранит `firstName` и `lastName` отдельно,
поле `name` собирается как «Фамилия Имя» и служит для сортировки и поиска.

- Форма справочника: два поля, «Фамилия» идёт первой, оба обязательны.
- Блок в расписании: первая строка — время и фамилия, вторая — имя.
- За 15 минут блок слишком низкий для двух строк, поэтому показывается
  «Фамилия И.» — инициал вместо полного имени.
- Список, месяц, заметки, сводка и карточка показывают «Фамилия Имя».
- Схема хранилища поднята до версии 2; миграция разбирает старое поле `name`
  на две части, поэтому существующие базы и старые копии JSON не теряют данные.
